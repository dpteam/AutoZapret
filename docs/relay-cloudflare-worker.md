# Внешний релей для Telegram (Cloudflare Worker)

Зачем: в сетях, где `kws*.web.telegram.org` блокируется **по адресу** (TCP не
открывается вообще), ни одна desync-стратегия не помогает. Прокси при этом
корректен — некуда подключаться.

Релей меняет адрес назначения: трафик идёт на `*.workers.dev`, а оттуда
Cloudflare открывает TCP к Telegram. Шифрование остаётся нашим: релей не видит
ни TLS, ни MTProto, ни секрета прокси.

```
Telegram  ->  наш прокси  ->  wss://ваш.workers.dev/?host=kws2.web.telegram.org&port=443
                                    |
                                    +-> Cloudflare открывает TCP к Telegram
                                    |
                              и по этому TCP мы делаем TLS + /apiws
```

## Что нужно сделать (5 минут, бесплатно)

1. Зарегистрироваться на [dash.cloudflare.com](https://dash.cloudflare.com/) и
   **подтвердить почту** — без этого Workers не включатся.
2. `Compute` → `Workers & Pages` → `Create` → `Start with Hello World` → `Deploy`.
3. `Edit code` → заменить всё содержимое на [`web/relay/worker.js`](../web/relay/worker.js)
   → `Deploy`.
4. Скопировать адрес из поля справа: `что-то-случайное.имя.workers.dev`.
5. В программе: `Настройки` → `Telegram-прокси` → `Внешний релей` → вставить
   адрес → `Проверить`. Должно появиться «Релей работает».

То же самое есть внутри программы: кнопка **«Как сделать свой?»** рядом с полем
релея. Код воркера там вшит и копируется одной кнопкой — интернет для этого не
нужен.

## Необязательно, но полезно: ключ доступа

Без ключа воркер — **открытый прокси для всего интернета**: любой, кто узнал
адрес, может гонять через вас трафик.

`Settings` → `Variables and Secrets` → добавить `KEY` со случайным значением.
Тогда адрес релея в программе должен быть с ключом:

```
wss://ваш.workers.dev/?key=СЕКРЕТ
```

Программа добавляет `host` и `port` сама, сохраняя ваш query.

## Несколько релеев

Поле принимает список через запятую, точку с запятой, пробел или перевод строки:

```
cdn.один.workers.dev, cdn.два.workers.dev
```

Пробуются по порядку. Первый рабочий запоминается на 120 секунд; упавший уходит
в карантин на 30 секунд. Если не ответил ни один — идёт обычный прямой путь
(он работает там, где блокировки по адресу нет).

## Проверка без программы

```
https://ваш.workers.dev/?probe=kws2.web.telegram.org:443
```

- `OK ...` — Cloudflare пускает, TCP до Telegram открывается;
- `FAIL ... -> причина` — вот и ответ, почему не работает.

То же самое из консоли:

```bat
AutoZapret.exe --relay-check ваш.workers.dev
AutoZapret.exe --relay-check "cdn.один.workers.dev, cdn.два.workers.dev"
```

## Почему именно этот код

В воркере важны три вещи, и все три — результаты уже набитых шишек:

1. **`await socket.opened`.** Без этого ошибка соединения приходит как
   «Stream was cancelled», и починить её невозможно: непонятно, что именно
   запретил Cloudflare. С ожиданием причина уходит в close-кадр и видна в
   программе.
2. **Диагностика только текстом до старта данных.** Первая версия отправляла
   ошибку текстовым кадром в тот же поток, где уже идёт TLS. Клиент получал
   «HTTP/1.1 400 Bad Request» посреди TLS-рукопожатия и падал с «wrong version
   number».
3. **Записи сериализованы.** Параллельные `writer.write` переставляют куски, и
   TLS-поток на той стороне разваливается.

## Ограничения Cloudflare

| Что | Значение | Следствие |
|---|---|---|
| Одновременных исходящих TCP на запрос | 6 | Нам хватает: одна сессия — один туннель |
| CPU на запрос (Free) | 10 мс | Перекладывание байт почти не тратит CPU |
| Длительность HTTP-запроса | нет лимита | WebSocket может висеть долго |
| Лимит запросов (Free) | 100 000/сутки | Считаются соединения, не байты |
| Порты | 25 запрещён | Нам не нужен |

Cloudflare **не разрешает** `connect()` к своим же адресам, `localhost` и
приватным сетям. `kws*.web.telegram.org` — это `149.154.167.99` (Telegram),
поэтому соединение разрешено.

## Если воркер не работает

| Симптом | Причина | Что делать |
|---|---|---|
| `FAIL ... -> proxy request failed, cannot connect to the specified address` | адрес запрещён Cloudflare | проверить `?probe=`, попробовать другой домен |
| `FAIL ... -> Stream was cancelled` | старый код без `await socket.opened` | заменить код на `web/relay/worker.js` |
| «сервер закрыл соединение на апгрейде» | воркер вернул не 101 | открыть `?probe=`, посмотреть причину |
| «wrong version number» | в туннель попал текст вместо данных | старый код отправлял ошибки в поток; обновить |
| `forbidden` | задан `KEY`, а в адресе его нет | добавить `?key=...` |
