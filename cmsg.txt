feat(P9): Windows autostart via Task Scheduler, with registry fallback

Two ways to start with Windows, and the choice is not cosmetic:

- Task Scheduler with /sc onlogon /rl HIGHEST starts the app ALREADY
  elevated. No UAC prompt. This is the only way autostart of a DPI
  bypass is tolerable: otherwise the user clicks Yes on every logon.
- HKCU\...\Run needs no rights to install, but winws still asks for UAC
  every single time the app enables the bypass.

So Enable() tries the task first and says honestly when rights are
missing instead of silently installing the weaker option. The GUI asks
the user, and if they decline, the registry path is used - declining
elevation is not the same as declining autostart.

Rights are raised for ONE operation, per AGENTS.md: creating the task
runs a short-lived child process ('--autostart enable') through UAC; the
GUI itself stays asInvoker and keeps no privileges afterwards.

'/delay 0000:30' on the task: network and the WinDivert driver need a
moment after logon, and a 0s start fails intermittently.

Stale detection: a portable build can be moved to another folder while
the task keeps pointing at the old path. Query() compares the configured
target with the current exe and the UI shows a warning with both paths.
A silently broken autostart is worse than no autostart.

Detection relies on the exit code of schtasks, never on its output text -
schtasks is localised and would parse differently on every Windows
language (same reason as the chcp 437 rule for netsh/sc).

Also wires settings.zapret.autoStart, which existed since P1 but was
never read: it now enables the bypass at launch. Without admin it is
skipped with a log line instead of raising UAC at logon, and the tray
notification appears only when the app was launched minimized (i.e. from
autostart), not on every manual launch.

CLI: --autostart status|enable|enable-run|disable (0 ok, 1 error,
2 needs elevation)
UI: 'Запуск' card with stale warning and a separate 'enable bypass at
start' switch
selftest: 15 checks, none of which touch the system - autostart is
verified end-to-end manually instead (enable-run, stale path, disable).
The registry value is written as quoted-path plus --minimized, status
detects it, a bogus path is reported as stale, disable removes it.
