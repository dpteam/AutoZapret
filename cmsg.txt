fix(ci): robocopy exit code, engine in artifacts, version from tag + RU/EN interface

Three defects reported from GitHub Actions, all real:

1. "Successful build, step failed with exit code 1". robocopy returns 1
   for "files were copied" - 0..7 is success, 8+ is failure. The Actions
   pwsh wrapper exits with $LASTEXITCODE of the last command, so a
   perfectly good copy failed the step. Now: explicit "-ge 8" check and
   $LASTEXITCODE reset, with a comment explaining why.

2. The self-contained artifact shipped WITHOUT engine\, so the app
   started and said "Engine is not installed". The release zip had the
   same hole and told the user to run tools\fetch-engine.ps1 - which was
   not in the archive either. Both workflows now put the engine inside,
   release fails outright if the engine is missing, and tools/ is
   packaged so the update instruction actually resolves.

3. Release never set the version from the tag: v0.3.0 built with
   <Version>0.2.0</Version> from csproj reports 0.2.0, so self-update
   offers 0.3.0 forever - download, install, still 0.2.0, repeat. A
   "Resolve version from tag" step now validates the tag shape and passes
   -p:Version/-p:FileVersion/-p:AssemblyVersion to build and publish, and
   the exe is asked for --version afterwards.

check-workflows.ps1 also learned to substitute ${{ ... }} before parsing:
Actions expands those placeholders before PowerShell sees them, but the
parser choked on them and reported false syntax errors.

Localisation RU/EN:
- en.json embedded as a resource, key = Russian source text (gettext
  style: msgid = source string), so no markup surgery across 650 lines.
  translateDom() walks text nodes plus placeholder/title attributes;
  dynamic labels go through t() and tf("{0} of {1}", ...).
- Boundary stated honestly in the settings hint: the INTERFACE is
  translated, while diagnostics and logs are produced in C# and stay
  Russian. Pretending otherwise would be a lie the first time someone
  opens the Diagnostics screen.
- selftest: 191 keys, valid JSON, no empty or untranslated values, no
  orphan keys (text edited but dictionary forgotten), templates keep
  their {0} placeholders.
- The orphan check caught itself: two keys I had added were unused, and
  a long hint split across two lines needed whitespace-normalised
  comparison.

me here: a literal "<script>" inside a comment in app.js breaks any tool
that injects markup into the page.
