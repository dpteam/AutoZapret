feat(P5): update channels, start-up check, and the missing app install button

Three gaps in the self-update path:

1. settings.updates.channel existed but nothing read it. Now
   SelfUpdater.Channel drives the lookup. Stable uses /releases/latest,
   which never returns pre-releases at all, so a stable user cannot be
   handed a beta by accident. Beta fetches the release list and picks
   the MAXIMUM version - the list is ordered by creation date, so
   'first entry' would offer an old hotfix tag over a newer release.

2. SanitizeTag used to reject any tag containing a hyphen. That is
   correct for stable and wrong for beta. It now takes allowPrerelease:
   -beta/-rc/-alpha/-pre pass only on the beta channel, while
   -fork/-custom/-anything-else is rejected on both. The rule the code
   exists for is unchanged: a fork tag must never look like an update.

3. There was no 'upd.app.install' handler and no button. The app could
   check for updates and then had no way to apply one - the whole
   self-update mechanism was reachable only from the CLI. Now it stops
   the bypass first (xcopy silently skips files locked by WinDivert),
   installs, and exits so the replacer can swap the exe.

HasUpdate now also handles the beta -> release transition: 1.3.0-beta1
to 1.3.0 compares equal numerically, so without an explicit check a beta
user would never be offered the final build. The reverse (release ->
beta) stays off.

Auto-check on start is quiet by design: it asks, and if something newer
exists only notifies. Installing without a click would restart the app
under the user's hands.

UI: 'Обновить' next to the app, and a channel selector.
selftest: 25 checks on the channel barrier, including the two
transitions above and 1.10.0 > 1.9 ordering.
