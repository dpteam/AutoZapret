fix: strategy picking stalled silently; own winws counted as foreign

Reported: "перебор стратегий не стартует, winws даже не спавнится".

Two defects stacked:

1. DetectForeignWinws() matches by process name only, so it found OUR
   OWN winws. Preflight then reported "already running another winws" and
   RunTestUi returned. Which brings us to...

2. That return was silent: no terminal diag.test message, so the button
   stayed on "…" forever. It looked like a hang with no process to blame.
   Every early exit now goes through AbortTest(reason), which always sends
   the final message.

   Our PIDs are now remembered on start and dropped on stop/exit, and
   DetectForeignWinws skips them. The check means what it says.

3. hosts can break the very thing it is meant to help: the block written
   by "Update hosts" redirected youtube.com and discord.com to hardcoded
   IPs, so the browser walked past the bypass and got a wrong certificate
   or a timeout. That is exactly the "ALT12 works but the browser does not
   open" report. Applying hosts now warns in the result line when the
   block contains sites the engine already bypasses, not just in the log.

Headless testing (so this can be checked without a dozen UAC prompts):
tools\headless.ps1 builds a temporary .cmd with a sequence of CLI commands,
launches it once through runas, and writes data\headless\report-*.txt.
Sets: safe (env/diag/preflight/probe/deep/tcp16/selftest), full (+ strategy
sweep), strategy (one strategy by id).

First real run, single UAC, 614 lines of report:

  baseline         google/twitch ok; youtube, ytimg, discord, discord-cdn,
                   telegram blocked

  tcp16            no volume break (7 of 8 survived 40 KB)

data/ is now ignored wholesale instead of by subdirectory: the headless
reports landed in an unreported folder and would have been committed by
"git add -A". Ignoring the parent means the next runtime folder cannot
slip through either.
