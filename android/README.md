# AutoZapret для Android

Отдельное приложение на **.NET 9 Android** (`net9.0-android`). Не часть
десктопной сборки и не влияет на `tools\ci-local.ps1`.

## Почему .NET, а не Kotlin

Telegram-прокси (`MtProtoHandshake`, `AesCtr`, `WsClient`, `WsTunnel`,
`MtProtoSplitter`) — чистый BCL: сокеты, `SslStream`, AES. Он переносится на
Android без переписывания. Kotlin-версия означала бы второй источник правды для
уже отлаженного протокола.

UI — те же файлы из `../web/` (`ui.html`, `app.js`, `theme.css`). Мост
`chrome.webview.postMessage` подменяется тонким шимом на `@JavascriptInterface`,
поэтому HTML не форкается.

## Тулчейн

Нужно один раз:

```
dotnet workload install android
```

(JDK 17+ и Android SDK ставит сам workload. `adb` нужен для установки на телефон.)

## Сборка

Один раз:

```
dotnet workload install android
dotnet build -t:InstallAndroidDependencies -f net9.0-android ^
    -p:AndroidSdkDirectory="C:\Android\sdk" -p:AcceptAndroidSDKLicenses=True
```

Дальше — `android\build.cmd` (сам подхватит `ANDROID_HOME` или `C:\Android\sdk`).

APK:

```
android\AutoZapret.Android\bin\Debug\net9.0-android\ru.autozapret.android-Signed.apk
```

Установка на подключённый телефон:

```
adb install -r android\AutoZapret.Android\bin\Debug\net9.0-android\ru.autozapret.android-Signed.apk
```

## Что уже работает

* Экран приложения (WebView, наша палитра): включение/выключение, порт,
  позиция разреза, пауза между частями, счётчики, лог.
* Локальный **SOCKS5 с разрезом TLS ClientHello**. Проверено на десктопе тем же
  кодом движка: получатель видит `Read → 5 байт`, `Read → 59 байт` вместо одного
  куска, байты не искажаются.
* **VPN-режим** (кнопка «VPN-режим: весь телефон»): `VpnService` создаёт tun,
  **hev-socks5-tunnel** (MIT) превращает его в TCP/UDP и ведёт в наш SOCKS5,
  где и делается обход. Архитектура как у ByeByeDPI, но без JNI: hev вызывается
  из C# через P/Invoke (`Engine/HevTunnel.cs`).
* **Выбор приложений** (`AppSelection.cs` + карточка в интерфейсе): весь телефон,
  «только выбранные», «все, кроме выбранных». Список — только приложения из
  лончера (`ACTION_MAIN` + `CATEGORY_LAUNCHER`), без системной мелочи.
  Зачем: банки и госуслуги ругаются на активный VPN, а заворачивать нужно не всё.
* **UDP в SOCKS5** (`UDP ASSOCIATE`, RFC 1928). Без него в VPN-режиме не было ни
  DNS, ни голоса: hev отдаёт сюда всё, что не TCP. На каждый ответ мы возвращаем
  заголовок с адресом отправителя, поэтому голос (много собеседников сразу)
  работает через один сокет. Два исходящих сокета — v4 и v6: с IPv4-сокета
  датаграмму на IPv6-адрес не отправить.
* **IPv6 в туннеле — по факту.** Если у активной сети есть глобальный IPv6,
  добавляется `fc00::1/128` и маршрут `::/0`, иначе туннель остаётся
  IPv4-only. Проверка через `ConnectivityManager`, а не «есть ли где-нибудь
  адрес»: на телефоне одновременно живут Wi-Fi без IPv6 и мобильная сеть с ним.
* Telegram: `Настройки → Прокси → Добавить → SOCKS5`, сервер `127.0.0.1`,
  порт из приложения. В VPN-режиме то же самое, но для всех приложений.

Пока приложение на экране (или свёрнуто ненадолго) — прокси работает; VPN-режим
живёт в foreground-сервисе с уведомлением.

## Сборка tun2socks

Один раз, до первой сборки APK:

```
android\build-hev.cmd
```

Скрипт соберёт `refs\hev-socks5-tunnel` через NDK (`arm64-v8a` + `x86_64`) и
положит `.so` в `AutoZapret.Android\libs\`. Готовые библиотеки в git не лежат.

Минимальная версия Android — **10 (API 29)**: под неё собрана hev.

## Нативные библиотеки: что реально возможно

Проверено сборкой, а не рассуждением.

**zapret (`winws`/`winws2`) под Android не собирается вообще.** Он перехватывает
трафик через WinDivert (`winws`) или NFQUEUE (`nfqws`) — оба требуют доступа к
сетевому стеку ядра. На Android без root этого нет ни у кого: root-права не
выдаёт даже системное приложение. В `refs/` от zapret лежат только бинарники —
исходников нет, и это не упущение, а лицензионная реальность бандла.

**byedpi (MIT, `refs/byedpi`) собирается под arm64 одной командой:**

```
aarch64-linux-android29-clang -D_DEFAULT_SOURCE -I. -std=c99 -O2 \
    packets.c main.c conev.c proxy.c desync.c mpool.c extend.c -o ciadpi
```

83 КБ, запускается на телефоне, `--version` отвечает `17.3`. Проверено на
Android 16 / arm64 через adb. Это рабочий путь, если понадобятся техники,
которых нет в C# (см. ниже).

## Что прошло на живой сети (МТС, Android 16)

Прогон `ciadpi` по одной технике за раз, цель `www.youtube.com` по IP
(чтобы исключить блокировку по SNI):

| Техника | Результат |
|---|---|
| без desync | таймаут 18 с |
| `--split 1` | таймаут 18 с |
| `--split 1+s` | таймаут 18 с |
| `--disorder 1` | таймаут 18 с |
| `--oob 1` | таймаут 18 с |
| `--auto=torst` | таймаут 18 с |
| `--tlsrec 1+s` | таймаут 18 с |
| **`--fake -1 --ttl 8`** | **200 OK за 0,57 с** |
| `--fake -1 --ttl 3` | таймаут |
| `--fake -1 --ttl 5` | таймаут |
| `--fake -1 --ttl 12` | таймаут |
| `--fake -1 --ttl 20` | таймаут |

Вывод, который определяет всю архитектуру Android-версии: **на этой сети
работает только фейк с низким TTL**. Разрез ClientHello, disorder и OOB DPI
собирает и блокирует целиком. Окно TTL узкое (8 работает, 3/5/12/20 — нет):
фейк должен умереть после DPI, но до сервера.

Отсюда `DesyncPreset.FakeTtl8` — и он реализован в нашем C# обычным `send()`
с `IP_TTL`. Никакой нативной библиотеки для этого не нужно.

## Подлог DNS — вторая половина проблемы

Даже с работающим обходом YouTube не открывался. Причина не в обходе:

```
www.youtube.com -> 198.18.0.4     (подлог)
discord.com     -> 198.18.0.74    (подлог)
twitch.tv       -> 151.101.194.167 (честно)
ya.ru           -> 5.255.255.242   (честно)
github.com      -> 4.225.11.194    (честно)
```

`198.18.0.0/15` — диапазон для тестовых сетей (RFC 2544). Настоящих серверов
там нет: пакет уходит в чёрную дыру. Оператор подменяет DNS **выборочно**, и
именно поэтому «YouTube не работает, а ya.ru работает».

Лечится своим резолвером через DoH (`Engine/Doh.cs`) плюс перехватом DNS в
UDP-ретрансляторе (`Engine/DnsServer.cs`): приложения в VPN резолвят сами,
поэтому честный ответ надо отдать им, а не только нашему прокси.

## Headless-управление (без тапов по экрану)

Тап по координатам — плохой способ проверять: при сдвиге верстки он попадает
в соседнюю строку, и замер врёт. За один вечер так дважды выбралась не та
техника. Поэтому есть `tools\android-headless.ps1`:

```
powershell -File tools\android-headless.ps1 state
powershell -File tools\android-headless.ps1 technique fake8
powershell -File tools\android-headless.ps1 vpn on
powershell -File tools\android-headless.ps1 check
powershell -File tools\android-headless.ps1 probe https://www.youtube.com/
powershell -File tools\android-headless.ps1 log
```

Внутри — широковещательные команды (`CommandReceiver`), ответы идут в logcat
с тегом `AutoZapret`. VPN поднимается не напрямую: сервис защищён
`BIND_VPN_SERVICE`, и снаружи adb его не запустит — команда идёт в активность,
а она уже поднимает сервис.

## Проверено на живом телефоне

### Где сейчас рвётся (открытая проблема)

Прокси-режим (SOCKS5 без VPN) работает: YouTube отдаёт 872 КБ, 200 OK.
VPN-режим не работает: браузер получает `ERR_TIMED_OUT`.

Что при этом проверено и работает:

| Проверка | Результат |
|---|---|
| byedpi под VPN имеет выход в сеть | да: 1.1.1.1 → 200, 56 КБ |
| наш SOCKS5 под VPN | да: 872 КБ через цепочку DoH → IP → byedpi |
| hev получает соединения из tun | да: 21 соединение из `10.10.10.10` |
| hev отдаёт их в прокси | да: 38 соединений на `:1081` |
| MTU туннеля | 1500 (было 8500) |
| UnderlyingNetworks | задан физической сетью, не VPN |

Значит обход и движок исправны, а ломается передача `tun → hev → прокси`.
Следующий шаг — разобрать, что hev делает с прочитанными из tun пакетами.

Инструмент: `tools\android-pipeline.ps1` — проходит цепочку сверху вниз
(процесс → tun → hev → порты → DNS → прокси → крупный ответ) и показывает
первый сломанный слой. Запускать после каждого изменения.

### Ловушки, стоившие времени

* **`dumpsys netstats` бесполезен для VPN-режима**: трафик уходит через tun,
  счётчики UID остаются нулями, видно только loopback. Он показывает «не
  работает» для полностью рабочего приложения.
* **Приложение резолвит имена само** и получает подлог `198.18.x`. Наш DoH
  спасает только те соединения, где приходит имя, а не готовый IP.
* **hev сам выставляет MTU** через `ioctl(SIOCSIFMTU)`, перекрывая
  `builder.SetMtu`. Если в конфиге hev 8500, а канал 1500 — крупные пакеты
  рвутся, и страница рисует скелет при живых соединениях.
* **`UnderlyingNetworks: Null`** означает, что у исключённого из VPN трафика
  нет маршрута. Брать надо физическую сеть, а не `cm.ActiveNetwork`: в момент
  `Establish` активной может оказаться сам VPN.
* **Движок надо запускать после `Establish`**, иначе его сокеты создаются при
  старом маршруте и после поднятия туннеля уходят в никуда.
* **`$pid` в PowerShell** — встроенная переменная, присвоение игнорируется.
  Из-за этого проверка потоков в пайплайне ложно падала.

### Ранее проверенное

Адаптивная иконка (`mipmap-anydpi-v26`) применяется на Android 8+, но PNG в
`mipmap-mdpi..xxxhdpi` остаются в APK и используются частью системы: списком
приложений в настройках, экраном недавних задач, некоторыми лаунчерами. В
шаблоне .NET там лежит робот — его и видит человек, хотя в лончере уже наш
значок.

`tools\android-icons.ps1` рисует тот же знак (стрелка сквозь разбитую стену) во
всех плотностях и удаляет `appicon_background.png` — единственный файл, который
оставался роботом. Проверено: `aapt2 dump badging` показывает наш
`appicon.xml`, а `appicon_background` в APK отсутствует.

**Лаунчер кэширует иконки.** Даже после переустановки Яндекс.Лаунчер показывал
старого робота, пока не сбросили его данные (`pm clear com.yandex.launcher`).
Сброс стирает раскладку рабочего стола — предупреждать человека, а не делать
молча.

### Foreground-сервис — не удобство, а условие работы

Прокси в активности не работает вообще, и это неочевидно:

```
UID=10331 blocked_state={blocked=APP_BACKGROUND, allowed=NONE,
                         effective=APP_BACKGROUND}
Firewall rule changed: 10331-background-default
```

Data-saver firewall режет **весь** фоновый трафик приложения. Любое соединение
висит до таймаута, хотя сеть в порядке. С foreground-сервисом та же проверка
даёт `procState=FGS, effective=NONE`.

Симптом, который сбивает с толку: из `adb shell` (uid 2000) тот же запрос
отвечает 200, из приложения — таймаут. Полдня диагностики уходит на поиск
«бага в движке», которого нет.

### `netstats` не показывает трафик приложений в VPN

При включённом туннеле `dumpsys netstats` для чужого UID остаётся на нулях:
наружу приложение ходит через tun, и в статистику UID попадает только
loopback-петля. Проверять работу по счётчикам netstats нельзя — покажет «не
работает» при полностью рабочем приложении. Смотреть надо на счётчики самого
приложения и на его экран.

### Проверено на живом телефоне
Тест на Android 16 (API 36), arm64:

* **SOCKS5**: `curl --socks5-hostname` через `adb forward` → `https://example.com`
  отвечает 200 за 0,34 с.
* **VPN**: tun0 `10.10.10.10/32` поднимается, браузер открывает сайты, в приложении
  счётчики растут (58 соединений, 34 КБ вверх / 41 КБ вниз), лог показывает
  `VPN включён: tun → SOCKS5 127.0.0.1:1080`.
* Остановка VPN убирает tun0 и возвращает сеть — проверено.

Что ломалось на первом запуске и как вылечено (чтобы не наступить снова):

| Симптом | Причина |
|---|---|
| `No assemblies found in .../.__override__` | Fast Deployment: Debug-APK был «оболочкой», сборки доливала IDE. `EmbedAssembliesIntoApk=true` |
| `SecurityException` при старте FGS | targetSdk 35 требует `FOREGROUND_SERVICE_SYSTEM_EXEMPTED` **и** одно из exact-alarm разрешений. У ByeByeDPI targetSdk 34, поэтому им хватает одного |
| SIGSEGV в `hev_task_new` | `hev_socks5_tunnel_init` нельзя звать без `hev_task_system_init` + `lwip_init`. Правильная точка входа одна — `hev_socks5_tunnel_main_from_str` |
| SOCKS: `host unreachable` по имени, по IP работает | `TcpClient.BeginConnect(host, …)` шёл в IPv6 первым и висел до таймаута ОС. Теперь имя разбираем сами: IPv4 первым, 6 с на адрес |
| В VPN-режиме «сайты не открываются», хотя соединения есть | В SOCKS5 не было `UDP ASSOCIATE`: DNS-запросы (это UDP) получали отказ, и браузер не мог разрезолвить имя. Голос в Discord — по той же причине |
| `PackageInfoFlags.MainActivity` не компилируется | Такого значения в биндинге нет. Список приложений берём через `QueryIntentActivities` с `Intent.ActionMain` + `CategoryLauncher` |
| Список приложений почти пустой (Android 11+) | Ограничение видимости пакетов. Нужен `QUERY_ALL_PACKAGES` в манифесте — он не спрашивается у человека, просто объявляется |
| После включения IPv6 в туннеле сайты перестали открываться (`ERR_CONNECTION_RESET`) | Маршрут `::/0` завернули в туннель, а глобального IPv6 у сети нет: hev сбрасывает такие соединения, и браузер на сброс не откатывается на IPv4. Теперь IPv6 заворачивается только если он реально есть у **активной** сети (`ConnectivityManager.ActiveNetwork` → `LinkProperties`), а не у любого интерфейса |

## Чего здесь не будет

* WinDivert и `winws.exe` — это Windows.
* Правки `hosts` — на Android только с root.
* Копий кода ByeByeDPI (GPL-3.0) — только идеи и своя реализация.
