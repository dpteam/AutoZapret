> **Это не VPN.** AutoZapret не меняет ваш IP и не отправляет трафик через чужой сервер.
> Он обходит систему глубокого анализа трафика (DPI) — то есть ровно то, что делает
> [zapret](https://github.com/bol-van/zapret). Никаких подписок, аккаунтов и серверов.

## Быстрый старт

Два способа — оба дают одно и то же приложение.

**Установщик** (появляется в «Приложения и возможности», удаляется штатно):

1. Скачайте `AutoZapret-<версия>-setup.exe` из [релизов](../../releases/latest).
2. Запустите. Администратор **не нужен** — установка идёт в ваш профиль.
3. Ярлык появится в меню «Пуск». Запустите **AutoZapret**.
4. Нажмите **⏻ Включить обход** — здесь UAC попросит права, и это нормально:
   движку нужен драйвер WinDivert, а он ставится только с правами.

**Портативный архив** (ничего не устанавливается, всё в одной папке):

1. Скачайте `AutoZapret-portable.zip` и распакуйте в папку без пробелов —
   например `C:\AutoZapret`.
2. Правый клик по `AutoZapret.exe` → **Запуск от имени администратора**.
3. Нажмите **⏻ Включить обход**.

4. Проверьте: откройте YouTube или Discord.

Не работает — нажмите **Диагностика** → **Подобрать стратегию**.
Это займёт несколько минут: программа переберёт стратегии именно на вашей сети.

> Если движок не скачан (чистая установка), на главной появится кнопка
> **Скачать движок** — git и PowerShell не нужны.

### Чем установщик отличается от архива

| | Установщик | Архив |
|---|---|---|
| Запись в «Приложения и возможности» | да | нет |
| Ярлыки, автозапуск | галочками в мастере | вручную |
| Обновление поверх | настройки и свои наборы сохраняются | распаковать заново |
| Удаление | предлагает убрать наш блок из `hosts` и остановить службу | вручную |
| Права на установку | не нужны | не нужны |
| Куда ставится | `%LOCALAPPDATA%\Programs\AutoZapret` | куда распаковали |

Проверить скачанное можно по `checksums.txt` из того же релиза:

```
certutil -hashfile AutoZapret-0.3.0-setup.exe SHA256
```

## Стратегии

Каталог собирается из четырёх независимых наборов. У разных провайдеров и разных DPI
выигрывают разные комбинации, поэтому наборов несколько — это не дубли, а разные школы.

| Набор | Движок | Сколько | Что это |
|---|---|---|---|
| **Flowseal** | zapret 1 (`winws.exe`) | 22 | `ALT1`…`ALT12`, `general`, `discord` — самый обкатанный набор |
| **StressOzz** | zapret 1 (`winws.exe`) | 71 | `Yv01`–`Yv35`, `v1`–`v10`, `Dv1`–`Dv17`, `gVideo1`–`gVideo11` |
| **Zapret-Mods** | zapret 1 (`winws.exe`) | 26 | игровые моды: Dota 2, Minecraft, EA, Fortnite, Shizapret |
| **DNS GANWO** | zapret 1 (`winws.exe`) | 22 | `ALT14`/`ALT15`, профили под Steam, DOUBLE FAKE, HOSTFAKESPLIT |
| **SnAnVl** | zapret 2 (`winws2.exe`) | 22 | те же имена, что у Flowseal, но с Lua-скриптами и `--lua-desync` |

Итого **141 стратегия для zapret 1 и 22 для zapret 2**.

Стратегии StressOzz изначально написаны для Linux (`/opt/zapret/...`, запуск через
`iptables`). В каталог они попадают через `tools/import-stressozz.js`, который
подставляет плейсхолдеры `${LISTS}` / `${BIN}` и **достраивает глобальные
`--wf-tcp` / `--wf-udp`** — без них winws стартует и не видит ни одного пакета.

Наборы Zapret-Mods и DNS GANWO — это `.bat`-файлы других авторов, разобранные нашим
парсером (`--import-strategies <каталог> --into-catalog`). Три ссылки на фейки из
них не существуют ни в одном бандле. Подмена сделана явно и записана в инструментах,
а не молча:

```
4pda.bin                             → tls_clienthello_4pda_to.bin
tls_clienthello_www_google_com_2.bin → tls_clienthello_www_google_com.bin
```

### Дубли между наборами
Разные авторы часто берут один и тот же набор техник и дают ему своё имя. В списке
это две строки, между которыми выбирают наугад. `tools/dedupe-catalog.js` сравнивает
**полный набор аргументов** (а не похожесть) и убирает повторы, оставляя штатный
набор. Сейчас дублей нет, и это проверяется selftest-ом.

### Откуда взялись новые наборы

| Репозиторий | Что взято | Что пропущено и почему |
|---|---|---|
| `peshk0v/Zapret-Mods` | 26 из 29 | 3 совпали по содержимому с уже имеющимися |
| `DNS GANWO` (форк Flowseal) | 22 из 45 | 22 совпали; 4 файла из папки «196 батники» ссылаются на `tls_clienthello_www_onetrust_com.bin`, которого **нет и у самого автора** — они нерабочие у него же |

Оба набора проверены `--check-bats`: все файлы, на которые ссылаются стратегии,
существуют. Аудит `--dry-run` на живом движке для них **не прогонялся** (нужны права
администратора) — это записано в ROADMAP.

### Свои стратегии

Свой набор `.bat` добавляется кнопкой **«Свои стратегии» → «Выбрать папку»**:
файлы разбираются так же, как наборы движка, и помечаются в списке как `(своя)`.
Свои стратегии лежат отдельно от кэша движка (`assets/strategies/strategies.custom.json`),
поэтому обновление движка их не затирает.

Обратно — **«Экспортировать»**: стратегии текущего движка записываются в `.bat`
рядом с программой (`exported-strategies\`), путями через `%BIN%`/`%LISTS%`/`%LUA%`.
Такой файл запускается без AutoZapret и переносится вместе с папкой.

**Подбор фейка.** Файл `.bin`, который стратегия отправляет как подставной пакет,
выбран автором набора под его провайдера. Кнопка **«Подобрать фейк»** перебирает
файлы того же вида (TLS к TLS, QUIC к QUIC), проверяет каждый обычной пробой и
сохраняет победителя как свою стратегию. Это долго — каждый вариант означает запуск
движка, поэтому кнопка во время перебора превращается в **«Остановить»**: найденное
до остановки сохраняется.

### Файл для друга (`.azconf.json`)

Кнопка **«Поделиться»** пишет одну стратегию в файл `.azconf.json` — это **данные,
а не программа**. `.bat` запускается сам по себе; такой файл можно открыть
блокнотом, прочитать и проверить до добавления.

Что в нём есть и чего в нём нет:

| | |
|---|---|
| Есть | имя, движок, заметка, цели, профили, аргументы |
| Есть | подпись «от кого» — попадёт в заметку при импорте |
| **Нет** | абсолютных путей (`C:\...`, `\\сервер\...`) |
| **Нет** | ссылок в сеть (`http://`, `https://`) |
| **Нет** | `..` — выхода из каталога |

Всё, что указывает на файл, идёт через `${BIN}`/`${LISTS}`/`${LUA}`/`${FAKES}`.
Это проверяется **при импорте**, а не только при экспорте: файл мог быть
отредактирован руками. Опасный аргумент — это отказ целиком, а не «выкинем строку
и продолжим»: иначе получится профиль, который ссылается на несуществующий список,
и виноватой будет выглядеть стратегия.

Те же операции из консоли:

```bat
AutoZapret.exe --import-strategies <каталог> [--as <префикс>] [--into-catalog]
AutoZapret.exe --check-bats <каталог> [--as <префикс>]
AutoZapret.exe --export-strategies <каталог> [--engine v1|v2] [--id <id>]
AutoZapret.exe --share-strategy <id> [--author "текст"] [--dir <каталог>]
AutoZapret.exe --import-conf <файл или каталог>
AutoZapret.exe --tune-fakes <id> [--max 30] [--no-save] [--seconds 600]
```

`--check-bats` — разобрать набор и сказать, чего в нём не хватает, **не добавляя**
его. Импорт без этой проверки проходит и на наборе, который ссылается на
несуществующие `.bin`: провал всплывёт при запуске, и виноватой будет стратегия.

`Ctrl+C` в консоли останавливает перебор так же, как кнопка.

**Копировать и удалить.** «Копировать» создаёт свою стратегию из выбранной — чтобы
поправить одну опцию и не потерять исходную. «Удалить свою» убирает только свои:
стратегию набора удалить нельзя, её вернёт обновление набора.

## Hosts: фиксы и свои наборы

Готовые записи для `hosts` собраны в **Исправления → «Фиксы и списки hosts»**.
Ставится галочка, нажимается «Применить выбранные» — записи попадают в редактор
выше, где их видно до сохранения. Дубли не появляются: то, что уже есть в файле,
пропускается.

| Тип | Что это |
|---|---|
| **Фикс** | зашитые адреса от нас: `Xbox / Microsoft`, `Wikia / Fandom` |
| **Встроенный** | файл из `assets/hosts` — работает без сети |
| **Скачиваемый** | Flowseal, dns.malw.link — обновляется из сети, кэш остаётся на случай её отсутствия |

Список прокручивается: наборов много, и без прокрутки кнопка «Применить» уезжает
вниз, а её нажимают сразу после выбора.

### Проверка маршрутов: адрес должен отдавать сертификат этого имени

Записать в `hosts` можно любой адрес, и файл будет выглядеть правильно. Но если
сервер по этому адресу отдаёт **чужой** сертификат, браузер откажется открывать
сайт — то есть запись не помогает, а ломает: имя, которое и так разрешалось,
теперь ведёт в никуда.

Именно это и было в большом наборе. Адрес `191.217.212.16` («WLRUS / regional
transit») отвечал на любой запрос сертификатом для `bretthart.top`, и на него
висели **148 имён**: Claude, ChatGPT, Gemini, Spotify, x.ai, авторизация Xbox,
JetBrains, NVIDIA. Все 148 были сломаны, и по виду файла этого не понять.

Проверить можно одной командой:

```
node tools/verify-hosts-routes.js assets/hosts/hosts-optimized.txt
node tools/verify-hosts-routes.js <файл> --all      :: все пары, не выборка
node tools/verify-hosts-routes.js <файл> --offline  :: только формат
```

Скрипт подключается к адресу с именем из записи (TLS SNI), смотрит, есть ли это
имя в сертификате, и сравнивает адрес с тем, что DNS отдаёт сейчас. Возвращает
`0`, если чужих сертификатов нет.

Отдельно: **«не отвечает» ≠ «сломан»**. У Telegram и `*.discord.media` TCP
соединяется, а TLS висит — это DPI режет по имени, и запись работает вместе с
обходом. Такие не трогаем.

Результат ревизии 2026-11-21: было 623 рабочих и 168 сломанных, стало
**766 рабочих, 0 сломанных**. Заодно убраны 4 записи на приватные адреса
(`10.22.234.59` и подобные): внутри чужой локальной сети они работают, у всех
остальных — таймаут.

### Паки исправлений: когда hosts не поможет

Адресом в `hosts` лечится не всё. Если DPI режет **первое UDP-рукопожатие**
игры, никакой адрес не поможет — пакет всё равно не дойдёт. Для таких случаев
есть отдельный раздел **«Исправления»**: пак меняет не адрес, а то, что делает
движок, или дополняет список обхода.

| Пак | Что делает |
|---|---|
| **TEKKEN 8 — матчи и голос (UDP)** | Добавляет к выбранной стратегии отдельный профиль: на игровых UDP-портах перед настоящим пакетом уходит подставной STUN, и DPI принимает его за начало соединения |
| **AWS / Cloudflare — доступ** | Кладёт 47 доменов в личный список обхода (`list-general-user.txt`) |

**Пак с правилом не меняет вашу стратегию.** Он делает её копию с добавленным
профилем и сохраняет как свою — она появится в списке на главной, и включить её
нужно самому. Иначе «применил фикс» означало бы «изменил то, чем пользуюсь», и
вернуть прежнее можно было бы только переустановкой.

**Про TEKKEN 8 и cutoff.** Правило в исходном виде приходит без
`--dpi-desync-cutoff`. Без него `winws --dry-run` отвечает предупреждением
`TRASH FLOOD configuration detected`: подставной пакет уходит на **каждый**
пакет игры, то есть трафик умножается на 12. В паке `cutoff=n2` добавлен
намеренно, и selftest падает, если его уберут.

**Про AWS / Cloudflare.** Из 47 домнов на этой линии **29 работают без обхода**,
режутся только три: `cloudflaressl.com`, `cloudflarestatus.com`, `pages.dev`
(проверено трижды: 0 из 3 против 3 из 3 у рабочих). Если у вас эти сайты и так
открываются, пак не нужен: обход применяется к рабочему трафику и иногда мешает.
Список идёт в личный файл — его видно на экране «Списки» и можно убрать.

Каждый пак показывает, **что именно проверено** на этом компьютере, и
предупреждение — до применения, а не в логе.

### YouTube: ловушки кэшей
С 19–20 октября 2026 РКН подменил кэширующие серверы YouTube, которые стоят в
России: имена остались прежними, а отдают они медленно или не отдают вовсе.
Браузер берёт сервер из списка, который вернул YouTube, попадает на ловушку —
и **видео висит, хотя страница и картинки открываются**.

Набор **«YouTube — ловушки кэшей (замедление)»** привязывает имена-ловушки к
`0.0.0.0`. Тогда YouTube выбирает следующий сервер из своего списка, и если с
зарубежными соединение есть — видео идёт.

| | |
|---|---|
| В наборе | **147 имён**, и все проверены: каждое ведёт в российскую сеть провайдера |
| Откуда | списки Дом.ру, Мегафон, МТС, Ростелеком из [issue #18271](https://github.com/Flowseal/zapret-discord-youtube/issues/18271) |
| Проверка | каждое имя резолвилось через `1.1.1.1` и Яндекс (`77.88.8.8`), адрес смотрелся в ipinfo.io |
| Чего в наборе нет | **77 имён, ведущих на рабочие зарубежные серверы** Google (DE/SE/US/PL/CH, AS15169), и **31 имя, которого не существует**. Записи в hosts не ускоряют YouTube — они убирают имя из выбора, и убрать хороший сервер значит оставить клиенту только ловушки |
| Ограничение | **не лечит всё**: если с зарубежными серверами связи нет, нужен VPN или WARP — блокировка ловушек не создаёт маршрут там, где его нет |

Список Дом.ру подтвердился полностью: все 39 имён ведут в сети ER-Telecom
(это и есть Дом.ру) — например `rr1---sn-xguxaxjvh-8v1e` → `188.234.140.76`,
AS9049 ER-Telecom.

Почему имён так много: ловушки у каждого провайдера свои. Лишнее имя, которого
у вас нет, ни на что не влияет — оно и так не резолвится. А **своё** имя, которого
нет в наборе, добавляется через «Свой набор» (см. ниже) — найти его можно в
DevTools → Network, оставив только адреса российских сетей.

**Тридцать одно имя из списков в issue оказалось выдуманным**, и это две разные
истории:

* **27** — дописанные номера. Авторы писали `rr1..rr10` «на всякий случай», хотя
  у тех семейств существуют только `rr1..rr5` (у одного — `rr1..rr8`). Пять из
  шести таких семейств оказались зарубежными целиком, то есть блок был выдуман
  и в номерах, и в смысле.
* **4** — целые семейства, где мертвы все номера `rr1..rr12`. Одно из них в issue
  называли «Торонто», три держались как «непроверенные».

Проверено резолвом каждого номера от `rr1` до `rr12`: граница чёткая. В наборе
их нет — блокировать нечего, а в списке они выглядели бы как настоящие ловушки.

**Непроверенных имён в наборе нет.** У каждого либо адрес, либо доказательство,
что резолвить нечего: исключение на догадке «наверное тоже не в России» — это
не основание блокировать.

Генерируется `tools/gen-youtube-traps.js` — все исключения записаны в нём с
доказательством по каждому имени. Перезапустите браузер после применения: он
держит DNS в кэше.

Проверить набор заново можно одной командой — она резолвит каждое имя через два
резолвера (Яндекс и `1.1.1.1`) и смотрит страну каждого адреса:

```
node tools/verify-youtube-traps.js            :: полная проверка, нужна сеть
node tools/verify-youtube-traps.js --offline  :: только формат, без сети
```

Возвращает `0`, если всё сходится, и печатает имена, которые стали вести за
границу или перестали резолвиться. Это не «доверьтесь списку», а способ
перепроверить его самому, когда YouTube снова начнёт тормозить.

Второй источник, [discussions/251](https://github.com/Flowseal/zapret-discord-youtube/discussions/251),
проверен и **не взят**: там hosts-блоков нет, 48 имён кэшей упоминаются в
`alt-svc-mapping-for-testing` — это конфиг браузера для HTTP/3, а не блокировка.

### Свой набор

Поле **«Свой набор»**: название и строки hosts. Вставлять можно как есть — с
комментариями, пустыми строками и лишним текстом:

```
162.159.142.170 static.wikia.nocookie.net
162.159.142.170   wikia.nocookie.net   # картинки вики
мусор
```

Сохранится только то, что похоже на пару «адрес имя». Набор попадёт в список
первым, с пометкой **«свой»**, и применяется галочкой как остальные. Крестик
рядом удаляет набор — записи, уже добавленные в `hosts`, при этом остаются.

Свои наборы лежат в `assets/hosts/fixes.user.json` и обновлением поставки не
задеваются.

## Про TCP timestamps (важно)

Часть стратегий защищает подставной пакет несовпадающим **TCP-timestamp**: сервер
видит фейк и выбрасывает его. Если в Windows метки времени выключены, этой защиты
нет вовсе — фейк долетает до сервера, тот видит два рукопожатия подряд и рвёт
соединение. Снаружи это выглядит как «стратегия не работает», причём выборочно:
стратегии с `badseq` работают, а с `ts` — нет.

Windows **по умолчанию метки времени не включает**. Включить один раз:

```powershell
# Терминал от имени администратора
netsh int tcp set global timestamps=enabled
```

Проверить:

```powershell
netsh int tcp show global
# RFC 1323 Timestamps : enabled
```

AutoZapret проверяет это сам при каждом запуске и предупреждает, если выбранная
стратегия использует `ts`, а метки выключены. 31 стратегия из 117 использует `ts`.

> Телефонам и телевизорам это не нужно — там своя реализация.

## Как это работает

```
AutoZapret.exe  (GUI, трей, один процесс)
      │
      ├── engine\bin\winws.exe   ──►  WinDivert  ──►  сеть
      │      (стратегии обхода DPI)
      │
      └── Telegram-прокси  ──►  kws*.web.telegram.org
```

`winws` запускается **напрямую**, а не через `.bat`: только так видно PID-дерево и
код выхода. Аргументы собираются в массив токенов и квотируются по правилам
MS C runtime — иначе путь с пробелом ломает команду.

Перехват идёт на уровне драйвера WinDivert. Это **не** прокси и не туннель:
пакеты остаются вашими, меняется только их форма — так, чтобы DPI не собрал
TLS-рукопожатие целиком.

### Служба Windows

Обход может работать без окна — службой, которая поднимается до входа в систему
и живёт после выхода из сессии. Управление: **Настройки → Служба Windows**.

| Кнопка | Что делает |
|---|---|
| Установить | Ставит службу в автозапуск (нужны права администратора) |
| Запустить | Запускает обход без окна |
| **Перезапустить** | Останавливает, ждёт выгрузки драйвера, запускает заново |
| Остановить | Останавливает службу |
| Удалить | Убирает службу из системы |

Тот же перезапуск есть в **меню иконки в трее** — пункт появляется, когда служба
установлена. Окно для этого открывать не нужно.

**«Применять стратегию сразу»** (переключатель там же, по умолчанию выключен) —
перезапускать службу автоматически при смене стратегии. По умолчанию выключено
намеренно: перезапуск рвёт все соединения на несколько секунд, и листать список
стратегий с включённым переключателем — значит терять загрузки на каждом клике.

**«Перезапустить» нужна не для красоты.** Служба читает `settings.json` один раз
при старте: поменяли стратегию в окне — служба об этом не узнает и продолжит
работать по прежней. В списке будет новая, а обход — по старой. Если служба
работает, над списком стратегий появляется предупреждение с этой же подсказкой.

Двух кнопок «Остановить → Запустить» для этого мало: `sc stop` возвращается
раньше, чем служба отпустила WinDivert, и следующий `sc start` падает на занятом
драйвере. Перезапуск выдерживает паузу между шагами.

## Если не работает

| Симптом | Что делать |
|---|---|
| Кнопка включения не реагирует | Проверьте баннер сверху: нет прав администратора |
| Обход включён, сайты не открываются | **Диагностика** → **Подобрать стратегию** |
| Работает YouTube, но не Discord | Выберите стратегию с меткой `Discord` |
| Работает, но через 10 минут отваливается | Проверьте **Диагностика** → обрыв на 16–20 КБ. Нужна стратегия с `split-seqovl` |
| «Уже работает другой winws» | Остановите чужую службу: `sc stop zapret` |
| Стратегии с `ts` не работают | Включите TCP timestamps (см. выше) |
| Поменял стратегию, а обход идёт по старой | Служба читает настройки только при старте: **Настройки → Служба Windows → Перезапустить** |
| Антивирус ругается на `WinDivert64.sys` | Это драйвер перехвата, а не вирус. Подробности ниже |
| Сайт открывается, но не туда, или «нет соединения» у всех стратегий | **Диагностика** → **Шаг 1в**: возможно, провайдер подменяет DNS |

<details>
<summary><b>Почему антивирус ругается и что делать</b></summary>

**WinDivert** — это драйвер перехвата трафика, и он же используется вредоносным ПО,
поэтому эвристика помечает его как `Not-a-virus:RiskTool.Multi.WinDivert`.
Подписью нашего exe это не лечится.

**Что делать:**
- Добавьте папку AutoZapret в исключения антивируса, **или**
- Отключите проверку потенциально нежелательных программ (PUA).

Если вы не доверяете — не запускайте. Это нормальная реакция, а не паранойя.

SmartScreen покажет предупреждение на неподписанной сборке:
**Подробнее** → **Выполнить в любом случае**.

</details>

## DNS: подмена и DoH

Провайдер может не резать сайт, а **подменять ответ DNS** — тогда браузер идёт
на заглушку, и ни одна стратегия обхода не поможет: обход работает с трафиком,
а трафик уходит не туда.

### Как проверить

**Диагностика → Шаг 1в → «Проверить»**, или из консоли:

```
AutoZapret.exe --dns-check
AutoZapret.exe --dns-check youtube.com discord.com   :: свои домены
```

Программа спрашивает одно и то же имя двумя путями — через системный DNS и
через DoH (HTTPS) — и показывает **оба ответа рядом**.

| Вердикт | Что значит |
|---|---|
| `ok` | Ответы совпадают — подмены нет |
| `differs` | Адреса разные, но это **не подмена**: у крупных сайтов geo-DNS и свои серверы в каждой сети |
| `stub` | Системный DNS вернул заглушку (`0.0.0.0`, приватный адрес, `198.18.x` от VPN-клиента) — это подмена |
| `no-system` | Системный DNS молчит, а DoH отвечает — похоже на перехват порта 53 |
| `no-doh` | DoH недоступен, судить нечем — и это само по себе находка |

**Почему «адреса разные» — не тревога.** Проверено на живой сети: `www.google.com`
через три разных резолвера даёт три разных адреса, и все три настоящие.
Поэтому «подмена» ставится только по признакам, которые geo-DNS не объясняет.
Проверка, которая кричит на нормальной сети, будет отключена после второго
ложного сигнала — и настоящую подмену уже никто не увидит.

Тот же смысл одной командой в termux или на любом Linux:

```
curl -v -I --doh-url https://cloudflare-dns.com/dns-query https://github.com
```

Если адрес в `Trying ...` не похож на настоящий адрес сайта — ответ подменён.

### Как включить DoH

| Где | Как | Стоит ли |
|---|---|---|
| **Браузер** (Windows, Linux, Android) | Chrome/Edge: Настройки → Конфиденциальность → **Использовать безопасный DNS** → «Свой» → `https://cloudflare-dns.com/dns-query`. Firefox: **DNS через HTTPS** → «Максимальная защита» | **Да, везде** |
| **Система, Windows** | **Настройки → Secure DNS в браузерах** (в программе) или вручную | Можно, если не нужны белые списки провайдера |
| **Система, телефон** | — | **Нет** |

**Про телефон — это важно.** На Android включайте DoH **только в браузере**, а
системный DNS оставляйте как есть. Иначе перестают работать белые списки
провайдера: запросы уходят мимо его резолвера, и разрешённые ресурсы,
доступные только через него, перестают открываться. Браузерное DoH закрывает
подмену там, где она реально мешает, и не ломает остальное.

### Если подмена найдена

1. Включите DoH в браузере — этого достаточно для сайтов.
2. Программа и так ходит через DoH при проверках: `Resolver` предпочитает DoH
   системному DNS, поэтому «0 из 4» у всех стратегий из-за подмены не будет.
3. Если DoH режут (`no-doh`), подмена остаётся — тогда нужен VPN или прокси,
   а не обход DPI.

## Linux

Отдельная сборка: тот же интерфейс и тот же каталог стратегий, но движок
другой — `nfqws` из zapret вместо `winws.exe`. Это один и тот же код с разными
источниками пакетов, поэтому **все 141 стратегия работают на Linux без
переделки** (проверено `nfqws --dry-run` на каждой).

```bash
# движок: скачивает nfqws под вашу архитектуру из релиза zapret
./linux/tools/fetch-engine.sh

# сборка
dotnet build linux/AutoZapret.Linux.csproj -c Release

# запуск: интерфейс откроется в браузере
cd linux/bin/Release/net9.0
./AutoZapret                 # покажет адрес и откроет браузер
./AutoZapret --no-browser    # только сервер
./AutoZapret --port 8099     # другой порт

# включить обход — только от root
sudo ./AutoZapret
```

| | Windows | Linux |
|---|---|---|
| Перехват | WinDivert (`winws.exe`) | NFQUEUE (`nfqws`) + iptables |
| Интерфейс | WebView2 | тот же HTML в браузере |
| Права | UAC | `sudo` |
| `hosts` | `%SystemRoot%\System32\drivers\etc\hosts` | `/etc/hosts` |

Интерфейс — **тот же самый** `web/ui.html`: мост подменяется шимом поверх
WebSocket, и `app.js` не меняется ни на строку. Поэтому кнопки, темы, переводы
и списки стратегий на Linux те же, что на Windows.

**Чего пока нет:** диагностики (подбор стратегии, пробы), hosts-редактора,
Telegram-прокси и самообновления — в интерфейсе они отвечают «на Linux пока не
реализовано» вместо молчания. Ядро, каталог стратегий и включение обхода
работают.

### Почему бывает медленно

Обход перехватывает не весь трафик, а **первые пакеты соединения** — там, где
рукопожатие и где DPI принимает решение. Дальше пакеты идут напрямую. Лимит
зашит в правила: `ct original packets 1-6` (nftables) или `connbytes 1:6`
(iptables).

Если обход заметно замедляет сеть, почти всегда причина одна из двух:

| Причина | Что делать |
|---|---|
| Стратегия делает `--dpi-desync-repeats=6` по огромному `ipset-all.txt` (33 000 подсетей) на портах 80/443 — лишние пакеты уходят на каждое соединение | Взять стратегию с меньшим числом повторов или сузить список |
| Список доменов слишком широкий (AWS, Cloudflare, чужие сервисы) — в обход уходит то, что и так работает | Почистить `list-general-user.txt`; проверить, что именно режется, через **Диагностика** |

Наш набор «AWS / Cloudflare — доступ» ставит 47 доменов, но проверено, что
**29 из них работают без обхода** — если у вас они открываются, пакет не нужен.

Правила живут в отдельной таблице (`nft list ruleset` → `ip autozapret`), поэтому
снимаются одной командой и не мешают чужому firewall.
