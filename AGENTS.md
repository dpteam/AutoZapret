# AGENTS.md — правила для агентов и людей

Проект: **AutoZapret**. Один exe на .NET Framework 4.8 / x64, UI на WebView2,
движок zapret рядом в `engine/`, Telegram WS-прокси внутри процесса.

Полный план — [`ROADMAP.md`](ROADMAP.md). Бриф — [`PROMPT.md`](PROMPT.md).
Исследование источников — [`docs/research/`](docs/research/).

---

## Жёсткие ограничения

1. **.NET 9 (`net9.0-windows`), x64.** Не .NET Framework 4.8, не .NET 5/6/8 —
   миграция сделана в 0.2.0. Windows 7/8.1 **не поддерживаются** (.NET 9 требует 10 1607+).
   `Environment.Is64BitProcess` проверяется на старте, иначе — внятный отказ.
   32-битного `winws.exe` не существует, `WinDivert64.sys` — единственный драйвер.
2. **Никаких сторонних библиотек, NuGet, app.config.** Только BCL:
   `System`, `System.Core`, `System.IO.Compression`, `System.Windows.Forms`.
   Исключение ровно одно — **WebView2 SDK** из `lib/webview2` (managed DLL,
   подключается как `/reference`, качается `tools\fetch-webview2.ps1`).
   Пакет `Microsoft.Web.WebView2` из NuGet **не использовать**: он тянет
   зависимости и MSBuild-таргеты.
3. **UI — WebView2, не WinForms-контролы.** Форма — только хост и трей. Вся вёрстка в `web/`,
   вшивается `/resource:`. WinForms нужен ровно для окна и `NotifyIcon`.
4. **Мост — только `chrome.webview.postMessage`.** `window.external` и COM-скриптинг
   запрещены: они «мертвы» и небезопасны.
   Обмен держим в двух функциях (`send` / `onMessage`) — это позволяет перенести
   тот же HTML на Android без переписывания UI.
5. **Запускать `winws.exe` напрямую**, не через `.bat`/`cmd start`. Иначе нельзя отследить
   PID-дерево и код выхода. Аргументы — массив токенов, сквотированный `CommandLine.Build`.
6. **Данные вместо кода.** Новая стратегия — запись в `assets/strategies/*.json`,
   а не `if (name == "ALT7")`. Новый фейк — запись в библиотеку.
7. **Код FluxRoute копировать нельзя.** GPL-3.0. Только идеи и переосмысленная реализация.
   zapret/zapret2/Flowseal — MIT (можно), WinDivert — LGPLv3 (отдельными файлами, не в exe).
8. **Публикация — self-contained single-file** (`publish.cmd`). .NET у пользователя
   быть не должно. Trimming и NativeAOT недоступны (WinForms), поэтому ~48 МБ — норма.

## Сборка и тесты

```bat
build.cmd                              :: быстрая сборка (нужен .NET 9 SDK)
publish.cmd                            :: self-contained single-file (~48 МБ, .NET внутри)
powershell -File tools\fetch-webview2.ps1
powershell -File tools\fetch-engine.ps1
AutoZapret.exe --selftest              :: пишет selftest.txt, код возврата 0/1
AutoZapret.exe --selftest --require-engine  :: строго: без движка падает
powershell -File tools\ci-test.ps1     :: всё сразу
```

Правило: **не коммитить, если `build.cmd` или `--selftest` не зелёные.**
Перед тестами остановить `AutoZapret.exe` и `winws.exe` (иначе файл занят и сборка падает).

**build.cmd против publish.cmd.** `build.cmd` — для разработки: быстро, но требует
.NET 9 на машине. `publish.cmd` — то, что отдаётся людям: self-contained single-file,
.NET не нужен. `WebView2Loader.dll` в single-file **не встраивается** (нативная
библиотека) — её копирует publish.cmd, без неё окно не запускается.

**Про skip и CI.** `engine/` в `.gitignore`, поэтому на чистом клоне проверки движка
дают `[skip]`, а не `[FAIL]` — иначе CI краснеет на нормальном состоянии.
CI качает движок (`tools\fetch-engine.ps1`) и запускает `--require-engine`,
чтобы проверки движка реально выполнялись.

## Стиль кода

- Namespace: `AutoZapret.<Area>` (`App`, `Core`, `Zapret`, `Lists`, `Payloads`, `Diag`,
  `Update`, `Proxy`, `Orchestrator`).
- Никаких `Console.WriteLine` из библиотечного кода — только `Log.*`.
- Логи: категория 3–6 символов (`APP`, `WINWS`, `PROXY`, `UPD`, `LIST`), сообщение без
  переносов строк (Log сам склеивает), **без секретов**, без путей пользователя на публичных экранах.
- Потоки именуются (`winws-supervisor`, `proxy-accept`, `probe-loop`), `IsBackground = true`.
- Любой сервис с состоянием: `Start()`, `Stop()`, `IsRunning`, событие `Failed`, `StatusLine()`.
- Все блокировки — `lock` на приватном объекте, **без I/O внутри**.
- `async/await` — можно и нужно для I/O; UI-поток не блокировать никогда.
- Долгие операции — с `CancellationToken`, чтобы выход из приложения был мгновенным.

## PowerShell-скрипты

- **Сохранять в UTF-8 с BOM.** Windows PowerShell 5.1 читает `-File` без BOM как ANSI
  и ломается на кириллице («Неожиданный токен }»).
- Проверять синтаксис:
  `[System.Management.Automation.Language.Parser]::ParseFile($path,[ref]$null,[ref]$errors)`.
- Не использовать `$args` как сплат-хэштебл — она автоматическая.
- PowerShell **не различает регистр** переменных: `$token` и `$Token` — одна переменная.
- В тестах сокетов помнить: `$array -ne $null` фильтрует массив; писать `[bool]$x`.
- Скрипты не должны печатать лишнего: тесты возвращают код выхода, CI на него смотрит.

## Работа с процессами и драйвером (самое опасное место)

| Правило | Почему |
|---|---|
| Убивать **всё дерево** PID, не только `winws.exe` | `winws` — cygwin-бинарь, может плодить потомков |
| `Kill(entireProcessTree: true)` + `WaitForExit(1500)` | иначе следующий старт падает на занятом порту/драйвере |
| Проверять `sc query WinDivert`, а не только процессы | **у kernel-службы драйвера нет процесса** — проверка по именам даёт ложное «остановлено» |
| `sc stop` + **polling до `STOPPED`** (до 10 с) + пауза 1500 мс | `sc stop` возвращается раньше выгрузки драйвера |
| `netsh`/`sc`/`tasklist` вызывать как `cmd /c chcp 437 >nul & <cmd>` и декодировать CP437 | на русской Windows вывод локализован, парсинг ломается |
| UAC-отмена = **ошибка**, а не «успех» | `Win32Exception 1223` надо обрабатывать явно |
| Повышение прав — только на операцию | манифест `asInvoker`, `runas` для конкретного действия |

## Безопасность

- **Секрет прокси** — 16 случайных байт (`RandomNumberGenerator`), в лог не пишем, в UI
  показываем только по кнопке «показать».
- **Прокси слушает `127.0.0.1`** по умолчанию. `0.0.0.0` — только по явному выбору,
  с предупреждением «будет доступен всей локальной сети».
- **Path traversal:** любой путь из UI/URL проходит через нормализацию и проверку «внутри
  разрешённых каталогов» (никаких `..`).
- **Скачанные файлы** (списки, фейки, обновления) — проверять: не HTML, размер в разумных
  пределах, формат валиден, SHA-256 сверяется с релизом.
- **`.bin`-фейк** перед подстановкой в `--dpi-desync-fake-tls` проходит валидатор
  (сигнатура TLS/QUIC/STUN), иначе winws молча шлёт мусор.
- **Не писать в `hosts`** без бэкапа и без кнопки «восстановить».

## Известные грабли

| Грабля | Решение |
|---|---|
| `WinDivert64.sys` детектится AV как `Not-a-virus:RiskTool.Multi.WinDivert` | подписью нашего exe не лечится; честный раздел в README + исключение Defender по согласию |
| `WinDivert64.sys` подписан **чужим** сертификатом (истёк 2023-05) | не переподписывать — нарушит лицензию; документировать |
| `sc stop` вернулся, а драйвер ещё жив | polling до `STOPPED` + пауза |
| Файлы `engine/` заняты при обновлении | 12 попыток × 250 мс, затем `*.upd` + `File.Move` |
| `winws`, запущенный через `cmd/start`, не убивается по своему PID | при `Stop()` в таком режиме убивать **все** `winws.exe` |
| Русская Windows ломает парсинг `netsh`/`sc` | `chcp 437` + CP437 |
| `ipset-all.txt` приходит с **CRLF** | нормализовать в LF при скачивании |
| Cloudflare целиком в `ipset-all.txt` | обязательный `--ipset-exclude`, предупреждение в UI |
| `fooling=ts` не работает | включить `netsh interface tcp set global timestamps=enabled` |
| Сеть сменилась во время пробы стратегии | пробу выбросить (сравнивать хэш сети **и** счётчик смен) |
| `SemaphoreSlim` не реентрантный | разделять `FooAsync()` (захватывает) и `FooCoreAsync()` (требует удержания) |
| `!domain` в hostlist | это **исключение**, а не цель |
| Битый `settings.json` | атомарная запись (temp → `File.Replace` → `.bak`), битый — в `*.corrupt-<ts>` |
| `%TEMP%` на другом диске | все временные файлы — рядом с целевым каталогом, иначе `File.Replace` не работает |
| Win7 без ESU | отдельная ветка `engine/win7` |
| Secure Boot на Win8/10 | может мешать WinDivert; документировать |
| 32-битная Windows | отказ на старте с внятным сообщением |
| SmartScreen на каждом билде | EV-сертификат или Azure Trusted Signing |
| **На машине разработчика уже стоит служба `zapret` от Flowseal** | Она держит `WinDivert` и уже перехватывает трафик. Перед любым тестом P1+ (запуск/остановка `winws`) — остановить её: `sc stop zapret` (и при необходимости `sc stop WinDivert`). Наш `Stop()` не должен убивать чужие процессы, но `winws`-процесс от службы он найдёт и убьёт — это осознанно и должно быть предупреждением в UI |
| **Антивирус блокирует скачивание zip-архива zapret-win-bundle** | Внутри `WinDivert64.sys`, который флагуется как RiskTool — AV рвёт загрузку архива целиком, хотя отдельные файлы проходят. **Качать только `git clone`**, не zip. `tools\fetch-engine.ps1` так и делает |
| `git clone` в PowerShell 5.1 падает при `ErrorActionPreference=Stop` | git пишет прогресс в stderr, а PS считает stderr ошибкой. Глушить `2>$null` и смотреть `$LASTEXITCODE`, временно ставя `Continue` |
| `echo engine -> path` в .cmd даёт «Отказано в доступе» | `>` — это редирект. Внутри блока `( ... )` он пытается писать в каталог. Экранировать: `-^>` |
| **`ProcessStartInfo.ArgumentList` не существует в net48** | Появился только в .NET Core 2.1+. В net48 — только строка `Arguments`, квотировать самому (`CommandLine.Build` по правилам MS C runtime) |
| `Process.Kill(entireProcessTree)` нет в net48 | Только .NET Core 3+. Дерево убивать через `taskkill /PID n /T /F` |
| `CodePagesEncodingProvider` нет в net48 | Только .NET Core. `Encoding.GetEncoding(866)` в net48 работает из коробки |
| **`--selftest` на CI падал** | `engine/` в `.gitignore`, на чистом клоне его нет, а проверки движка считались провалом. Теперь отсутствие движка = `[skip]`, а строгий режим включается флагом `--require-engine` (CI качает движок и запускает строго) |
| **v2 давал 0 стратегий** | В конфигах zapret2 после `^` идёт **пустая строка**, и cmd её проглатывает. `JoinContinuations` пустые строки не глотал → команда обрывалась на первом `^`. Теперь глотает |
| **v2 импорт стирал все v1** | При 0 импортированных стратегий `engine` брался по умолчанию (`"v1"`), и `RemoveAll` сносил v1. Теперь при пустом импорте выходим **до** удаления |
| **Жадный regex съедал имена опций** | `--hostlist=C:\...\lists\x.txt` превращался в `${LISTS}/x.txt`. Правильно: подставлять плейсхолдеры прямо в `ExpandVariables`, а не угадывать пути обратной заменой |
| `winws2` не считается за `winws` | У zapret2 процесс называется `winws2`. Проверка только `GetProcessesByName("winws")` даёт ложное «движок не запустился». Использовать `WinwsSupervisor.AnyWinwsRunning()` |
| **IPv4 и IPv6 для одного имени — не конфликт** | В hosts спокойно живут обе записи (двухстек). Конфликт — только два разных адреса внутри одного семейства. Иначе 20 «конфликтов» из ниоткуда |
| `out`-параметр внутри `&&` не считается присвоенным | `a.TryGetValue(k, out v) && v != null` — компилятор не гарантирует присвоение. Объявлять `string v = null;` заранее |
| **`WebView2Loader.dll` не попадает в single-file** | Это нативная библиотека, не managed. `CopyToOutputDirectory` её в publish не переносит — копировать явно в `publish.cmd`, иначе `DllNotFoundException` при создании окружения WebView2 |
| **WFO0003 про DPI** | С .NET 6 WinForms требует `ApplicationHighDpiMode` в csproj (или `SetHighDpiMode`), а не `<dpiAware>` в манифесте. Иначе предупреждение и режим может не примениться |

## Definition of done

- [ ] `build.cmd` без ошибок и без новых предупреждений (кроме осознанных).
- [ ] `AutoZapret.exe --selftest` → `RESULT: ok`.
- [ ] Новая фаза отмечена в `ROADMAP.md` (`[x]`), новые грабли — в таблице выше.
- [ ] Новые настройки — в `settings.json` (дефолты + миграция), в UI и в README.
- [ ] Никаких секретов и приватных путей в логах.
- [ ] Русский текст в `.md` — UTF-8, в `.ps1` — UTF-8 **с BOM**.
- [ ] `refs/`, `engine/`, `bin/`, `data/state/` не попали в коммит.
