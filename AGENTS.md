# AGENTS.md — правила для агентов и людей

Проект: **AutoZapret**. Один exe на .NET Framework 4.8 / x64, UI на WebView2,
движок zapret рядом в `engine/`, Telegram WS-прокси внутри процесса.

Полный план — [`ROADMAP.md`](ROADMAP.md). Бриф — [`PROMPT.md`](PROMPT.md).
Исследование источников — [`docs/research/`](docs/research/).

---

## Жёсткие ограничения

1. **.NET 9 (`net9.0-windows`), x64.** Не .NET Framework 4.8, не .NET 5/6/8 —
   миграция сделана в 0.2.0. Windows 7/8.1 **не поддерживаются** (.NET 9 требует 10 1607+).
   `Environment.Is64BitProcess` проверяется на старте, иначе — внятный отказ.
   32-битного `winws.exe` не существует, `WinDivert64.sys` — единственный драйвер.
2. **Никаких сторонних библиотек, NuGet, app.config.** Только BCL:
   `System`, `System.Core`, `System.IO.Compression`, `System.Windows.Forms`.
   Исключение ровно одно — **WebView2 SDK** из `lib/webview2` (managed DLL,
   подключается как `/reference`, качается `tools\fetch-webview2.ps1`).
   Пакет `Microsoft.Web.WebView2` из NuGet **не использовать**: он тянет
   зависимости и MSBuild-таргеты.
3. **UI — WebView2, не WinForms-контролы.** Форма — только хост и трей. Вся вёрстка в `web/`,
   вшивается `/resource:`. WinForms нужен ровно для окна и `NotifyIcon`.
4. **Мост — только `chrome.webview.postMessage`.** `window.external` и COM-скриптинг
   запрещены: они «мертвы» и небезопасны.
   Обмен держим в двух функциях (`send` / `onMessage`) — это позволяет перенести
   тот же HTML на Android без переписывания UI.
5. **Запускать `winws.exe` напрямую**, не через `.bat`/`cmd start`. Иначе нельзя отследить
   PID-дерево и код выхода. Аргументы — массив токенов, сквотированный `CommandLine.Build`.
6. **Данные вместо кода.** Новая стратегия — запись в `assets/strategies/*.json`,
   а не `if (name == "ALT7")`. Новый фейк — запись в библиотеку.
7. **Код FluxRoute копировать нельзя.** GPL-3.0. Только идеи и переосмысленная реализация.
   zapret/zapret2/Flowseal — MIT (можно), WinDivert — LGPLv3 (отдельными файлами, не в exe).
8. **Публикация — self-contained single-file** (`publish.cmd`). .NET у пользователя
   быть не должно. Trimming и NativeAOT недоступны (WinForms), поэтому ~48 МБ — норма.

## Сборка и тесты

```bat
build.cmd                              :: быстрая сборка (нужен .NET 9 SDK)
publish.cmd                            :: self-contained single-file (~48 МБ, .NET внутри)
powershell -File tools\fetch-webview2.ps1
powershell -File tools\fetch-engine.ps1
AutoZapret.exe --selftest              :: пишет selftest.txt, код возврата 0/1
AutoZapret.exe --selftest --require-engine  :: строго: без движка падает
powershell -File tools\ci-test.ps1     :: проверки без пакета (быстро)
powershell -File tools\ci-local.ps1    :: ПОЛНЫЙ локальный CI (+артефакт в artifacts\)
powershell -File tools\ci-local.ps1 -Publish  :: + self-contained пакет
powershell -File tools\headless.ps1 -Set safe :: прогон с ОДНИМ UAC (нужен админ)
```

**Правило: не коммитить, если `tools\ci-local.ps1` не зелёный.**
Это наш собственный CI — GitHub Actions иногда деградирует или ставит задачу
в очередь навсегда, и ждать его бессмысленно. `ci-local.ps1` делает то же
самое локально: workflow-файлы, кодировки, целостность UI, словарь переводов,
сборка без предупреждений, `--selftest`, строгий selftest с движком,
расширенный диагностический отчёт и пакет. Результат — `artifacts\`
(`autozapret-<версия>-<sha>.zip`, `ci-*.log`, `last-run.txt`, `diag\`).

Перед тестами остановить `AutoZapret.exe` и `winws.exe` (иначе файл занят и сборка падает).

**build.cmd против publish.cmd.** `build.cmd` — для разработки: быстро, но требует
.NET 9 на машине. `publish.cmd` — то, что отдаётся людям: self-contained single-file,
.NET не нужен. `WebView2Loader.dll` в single-file **не встраивается** (нативная
библиотека) — её копирует publish.cmd, без неё окно не запускается.

**Про skip и CI.** `engine/` в `.gitignore`, поэтому на чистом клоне проверки движка
дают `[skip]`, а не `[FAIL]` — иначе CI краснеет на нормальном состоянии.
CI качает движок (`tools\fetch-engine.ps1`) и запускает `--require-engine`,
чтобы проверки движка реально выполнялись.

## Стиль кода

- Namespace: `AutoZapret.<Area>` (`App`, `Core`, `Zapret`, `Lists`, `Payloads`, `Diag`,
  `Update`, `Proxy`, `Orchestrator`).
- Никаких `Console.WriteLine` из библиотечного кода — только `Log.*`.
- Логи: категория 3–6 символов (`APP`, `WINWS`, `PROXY`, `UPD`, `LIST`), сообщение без
  переносов строк (Log сам склеивает), **без секретов**, без путей пользователя на публичных экранах.
- Потоки именуются (`winws-supervisor`, `proxy-accept`, `probe-loop`), `IsBackground = true`.
- Любой сервис с состоянием: `Start()`, `Stop()`, `IsRunning`, событие `Failed`, `StatusLine()`.
- Все блокировки — `lock` на приватном объекте, **без I/O внутри**.
- `async/await` — можно и нужно для I/O; UI-поток не блокировать никогда.
- Долгие операции — с `CancellationToken`, чтобы выход из приложения был мгновенным.

## PowerShell-скрипты

- **Сохранять в UTF-8 с BOM.** Windows PowerShell 5.1 читает `-File` без BOM как ANSI
  и ломается на кириллице («Неожиданный токен }»).
- Проверять синтаксис:
  `[System.Management.Automation.Language.Parser]::ParseFile($path,[ref]$null,[ref]$errors)`.
- Не использовать `$args` как сплат-хэштебл — она автоматическая.
- PowerShell **не различает регистр** переменных: `$token` и `$Token` — одна переменная.
- В тестах сокетов помнить: `$array -ne $null` фильтрует массив; писать `[bool]$x`.
- Скрипты не должны печатать лишнего: тесты возвращают код выхода, CI на него смотрит.

## Работа с процессами и драйвером (самое опасное место)

| Правило | Почему |
|---|---|
| Убивать **всё дерево** PID, не только `winws.exe` | `winws` — cygwin-бинарь, может плодить потомков |
| `Kill(entireProcessTree: true)` + `WaitForExit(1500)` | иначе следующий старт падает на занятом порту/драйвере |
| Проверять `sc query WinDivert`, а не только процессы | **у kernel-службы драйвера нет процесса** — проверка по именам даёт ложное «остановлено» |
| `sc stop` + **polling до `STOPPED`** (до 10 с) + пауза 1500 мс | `sc stop` возвращается раньше выгрузки драйвера |
| `netsh`/`sc`/`tasklist` вызывать как `cmd /c chcp 437 >nul & <cmd>` и декодировать CP437 | на русской Windows вывод локализован, парсинг ломается |
| UAC-отмена = **ошибка**, а не «успех» | `Win32Exception 1223` надо обрабатывать явно |
| Повышение прав — только на операцию | манифест `asInvoker`, `runas` для конкретного действия |

## Безопасность

- **Секрет прокси** — 16 случайных байт (`RandomNumberGenerator`), в лог не пишем, в UI
  показываем только по кнопке «показать».
- **Прокси слушает `127.0.0.1`** по умолчанию. `0.0.0.0` — только по явному выбору,
  с предупреждением «будет доступен всей локальной сети».
- **Path traversal:** любой путь из UI/URL проходит через нормализацию и проверку «внутри
  разрешённых каталогов» (никаких `..`).
- **Скачанные файлы** (списки, фейки, обновления) — проверять: не HTML, размер в разумных
  пределах, формат валиден, SHA-256 сверяется с релизом.
- **`.bin`-фейк** перед подстановкой в `--dpi-desync-fake-tls` проходит валидатор
  (сигнатура TLS/QUIC/STUN), иначе winws молча шлёт мусор.
- **Не писать в `hosts`** без бэкапа и без кнопки «восстановить».

## Известные грабли

| Грабля | Решение |
|---|---|
| `WinDivert64.sys` детектится AV как `Not-a-virus:RiskTool.Multi.WinDivert` | подписью нашего exe не лечится; честный раздел в README + исключение Defender по согласию |
| `WinDivert64.sys` подписан **чужим** сертификатом (истёк 2023-05) | не переподписывать — нарушит лицензию; документировать |
| `sc stop` вернулся, а драйвер ещё жив | polling до `STOPPED` + пауза |
| Файлы `engine/` заняты при обновлении | 12 попыток × 250 мс, затем `*.upd` + `File.Move` |
| `winws`, запущенный через `cmd/start`, не убивается по своему PID | при `Stop()` в таком режиме убивать **все** `winws.exe` |
| Русская Windows ломает парсинг `netsh`/`sc` | `chcp 437` + CP437 |
| `ipset-all.txt` приходит с **CRLF** | нормализовать в LF при скачивании |
| Cloudflare целиком в `ipset-all.txt` | обязательный `--ipset-exclude`, предупреждение в UI |
| `fooling=ts` не работает | включить `netsh interface tcp set global timestamps=enabled` |
| Сеть сменилась во время пробы стратегии | пробу выбросить (сравнивать хэш сети **и** счётчик смен) |
| `SemaphoreSlim` не реентрантный | разделять `FooAsync()` (захватывает) и `FooCoreAsync()` (требует удержания) |
| `!domain` в hostlist | это **исключение**, а не цель |
| Битый `settings.json` | атомарная запись (temp → `File.Replace` → `.bak`), битый — в `*.corrupt-<ts>` |
| `%TEMP%` на другом диске | все временные файлы — рядом с целевым каталогом, иначе `File.Replace` не работает |
| Win7 без ESU | отдельная ветка `engine/win7` |
| Secure Boot на Win8/10 | может мешать WinDivert; документировать |
| 32-битная Windows | отказ на старте с внятным сообщением |
| SmartScreen на каждом билде | EV-сертификат или Azure Trusted Signing |
| **На машине разработчика уже стоит служба `zapret` от Flowseal** | Она держит `WinDivert` и уже перехватывает трафик. Перед любым тестом P1+ (запуск/остановка `winws`) — остановить её: `sc stop zapret` (и при необходимости `sc stop WinDivert`). Наш `Stop()` не должен убивать чужие процессы, но `winws`-процесс от службы он найдёт и убьёт — это осознанно и должно быть предупреждением в UI |
| **Антивирус блокирует скачивание zip-архива zapret-win-bundle** | Внутри `WinDivert64.sys`, который флагуется как RiskTool — AV рвёт загрузку архива целиком, хотя отдельные файлы проходят. **Качать только `git clone`**, не zip. `tools\fetch-engine.ps1` так и делает |
| `git clone` в PowerShell 5.1 падает при `ErrorActionPreference=Stop` | git пишет прогресс в stderr, а PS считает stderr ошибкой. Глушить `2>$null` и смотреть `$LASTEXITCODE`, временно ставя `Continue` |
| `echo engine -> path` в .cmd даёт «Отказано в доступе» | `>` — это редирект. Внутри блока `( ... )` он пытается писать в каталог. Экранировать: `-^>` |
| **`ProcessStartInfo.ArgumentList` не существует в net48** | Появился только в .NET Core 2.1+. В net48 — только строка `Arguments`, квотировать самому (`CommandLine.Build` по правилам MS C runtime) |
| `Process.Kill(entireProcessTree)` нет в net48 | Только .NET Core 3+. Дерево убивать через `taskkill /PID n /T /F` |
| `CodePagesEncodingProvider` нет в net48 | Только .NET Core. `Encoding.GetEncoding(866)` в net48 работает из коробки |
| **`--selftest` на CI падал** | `engine/` в `.gitignore`, на чистом клоне его нет, а проверки движка считались провалом. Теперь отсутствие движка = `[skip]`, а строгий режим включается флагом `--require-engine` (CI качает движок и запускает строго) |
| **v2 давал 0 стратегий** | В конфигах zapret2 после `^` идёт **пустая строка**, и cmd её проглатывает. `JoinContinuations` пустые строки не глотал → команда обрывалась на первом `^`. Теперь глотает |
| **v2 импорт стирал все v1** | При 0 импортированных стратегий `engine` брался по умолчанию (`"v1"`), и `RemoveAll` сносил v1. Теперь при пустом импорте выходим **до** удаления |
| **Жадный regex съедал имена опций** | `--hostlist=C:\...\lists\x.txt` превращался в `${LISTS}/x.txt`. Правильно: подставлять плейсхолдеры прямо в `ExpandVariables`, а не угадывать пути обратной заменой |
| `winws2` не считается за `winws` | У zapret2 процесс называется `winws2`. Проверка только `GetProcessesByName("winws")` даёт ложное «движок не запустился». Использовать `WinwsSupervisor.AnyWinwsRunning()` |
| **Порт в фильтре WinDivert — условие работы, а не оптимизация** | Пакет, который ядро не отдало, движок не увидит никогда. Фильтр обязан включать порты **всех** профилей (у discord это 2053/2083/2087/2096/8443), иначе профиль «есть», техника выбрана, а обхода нет — и в логах пусто |
| **`a or b and c` в фильтре WinDivert = `a or (b and c)`** | Условие `PayloadLength` приклеивается только к последнему порту. Список портов — всегда в скобках: `(tcp.DstPort == 443 or tcp.DstPort == 8443) and tcp.PayloadLength > 40` |
| **Опция TCP MD5 — 18 байт, а заголовок должен быть кратен 4** | `20 + 18 = 38` не делится на 4, и `data offset` такое не выражает. Нужно 2 байта выравнивания (NOP), иначе заголовок 40 байт не сходится с полем, и пакет разваливается у получателя. Ловится только разбором собранного пакета в selftest |
| **Протокол определять до разбора TCP** | `TcpPacket.Parse` на UDP возвращает `null`, поэтому UDP-ветка не вызывается, если её выбирать «по технике». Протокол читается из IP-заголовка (`packet[9]`), и только потом разбор |
| **SCM запускает службу без действия** | `sc create binPath= "...exe" --service` → аргументов нет. Действие по умолчанию обязано быть `run`, иначе служба печатает статус, выходит, и SCM отдаёт 1053 |
| **Служба от `LocalSystem` видит чужой `%LocalAppData%`** | Она прочитала бы не тот `settings.json` и запустила стратегию по умолчанию. В режиме службы — `Paths.ForcePortable()` |
| **`window.confirm` не умеет заставить подождать** | У системного диалога одна кнопка и никакого отсчёта, а предупреждения читают первые два раза. Для необратимых действий — `dangerConfirm()`: «Отмена» сразу, «ОК» с отсчётом, потом второе предупреждение. Ожидание пропорционально цене ошибки: hosts 5 с, удаление службы 10 с, `0.0.0.0` для SOCKS5 30 с |
| **Система осталась с DNS 127.0.0.1, а резолвер в этом же процессе** | Закрыли программу / упала / порт 53 заняли — и DNS нет вовсе, интернета нет, «выключить обход» не помогает. Решение в три слоя: (1) рядом с `127.0.0.1` всегда ставится запасной сервер (прежний или 1.1.1.1); (2) при выходе и в `Dispose` системный DNS возвращается ДО остановки резолвера; (3) сторож раз в 30 с поднимает резолвер или возвращает DNS |
| **Переключение системного DNS без проверки, что он отвечает** | `SelfCheck()` перед переключением: запрос к себе и требование NOERROR + хотя бы одна запись. SERVFAIL — это «ответ», но с ним интернета нет, и Windows на запасной сервер не переключится |
| **`document.body.classList` в статическом анализе** | Не путать с переменной `body`: `tools\check-ui-vars.js` ловит именно необъявленные переменные (`renderHosts` → `apply`, `renderSystemDns` → `on`), из-за которых обработчик умирает молча |
| **Переключение движка не должно трогать стратегию, если список тот же** | У zapret 1 и «своего» движка это ОДНИ И ТЕ ЖЕ стратегии. Меняется исполнитель, а не правила: сбрасывать выбор в этом случае — это баг, который выглядит как «перекинуло на первый» |
| **`Normalize()` знал только `v1`/`v2` — `own` тихо превращался в `v1` при `Save()`** | Симптом: выбрал свой движок, программа остановила winws и тут же запустила winws заново. Причина: `Save()` нормализует поля, и новое допустимое значение надо добавлять во ВСЕ списки (`Normalize`, `FromMap`, `OneOf`), иначе оно молча заменяется первым допустимым. Ловится только полным циклом save → load |
| **Двойной старт движка = «A copy of winws is already running with the same filter»** | Два `StartEngine` в одну миллисекунду поднимают два winws: второй выходит с кодом 1 и пишет ошибку, а первый работает. Со стороны — «обход не включился», хотя включился. Запуск сериализован (`_engineStartGate`), повторный запрос отклоняется |
| **Остатки своего winws держат фильтр, а PID их уже не знает** | После аварии/двойного старта остаётся процесс, которого нет в `_trackedPids`. Убивать по имени нельзя — рядом может стоять чужой winws от службы Flowseal. Только по **пути к exe** внутри `engine\bin` (`IsOurEngineExe`): `Stop()` добивает по пути, `Start()` снимает остатки перед запуском, а на «already running with the same filter» делает одну повторную попытку |
| **Смена секрета прокси не доходила до работающего прокси** | `secret.regenerate` менял только `settings.ProxySecret`, а `TgProxyServer._secret` копируется в `Start` и остаётся старым. Человек копирует НОВУЮ ссылку в Telegram, клиент приходит с новым секретом, прокси расшифровывает старым → «неизвестный proto tag». Теперь `UpdateSecret()` меняет секрет на ходу, а отказ классифицируется (`HandshakeReject`): Secret / Tls (`ee`) / Http / Garbage — советы разные |
| **`select.value = x` при отсутствии такого пункта молча ставит ПЕРВЫЙ** | Список перестроили, выбранного id в нём нет — браузер берёт первый пункт. Проверять `hasOption()` перед присваиванием |
| **Разбор конфигов winws без учёта неподдержанного врёт** | Стратегия, из которой молча выкинули половину опций, «работает» ровно настолько, чтобы виноватым оказался движок. Каждую неподдержанную опцию — в `Unsupported` с причиной, каждый выброшенный профиль — в `Dropped` |
| **v2-стратегия разбирается в профили без техник** | У `--lua-desync` есть `--filter-tcp` и списки, поэтому парсер соберёт набор профилей — и он будет «работать», ничего не делая. Флаг `Lua` обнуляет профили, а не оставляет их пустыми на вид |
| **IPv4 и IPv6 для одного имени — не конфликт** | В hosts спокойно живут обе записи (двухстек). Конфликт — только два разных адреса внутри одного семейства. Иначе 20 «конфликтов» из ниоткуда |
| `out`-параметр внутри `&&` не считается присвоенным | `a.TryGetValue(k, out v) && v != null` — компилятор не гарантирует присвоение. Объявлять `string v = null;` заранее |
| **`WebView2Loader.dll` не попадает в single-file** | Это нативная библиотека, не managed. `CopyToOutputDirectory` её в publish не переносит — копировать явно в `publish.cmd`, иначе `DllNotFoundException` при создании окружения WebView2 |
| **WFO0003 про DPI** | С .NET 6 WinForms требует `ApplicationHighDpiMode` в csproj (или `SetHighDpiMode`), а не `<dpiAware>` в манифесте. Иначе предупреждение и режим может не примениться |
| **`robocopy` возвращает 1 при успехе** | Коды 0–7 — успех (1 = «файлы скопированы»), 8+ — ошибка. В GitHub Actions `pwsh` возвращает `$LASTEXITCODE` последней команды, поэтому шаг падал с «exit code 1» при полностью успешном копировании. Проверять `-ge 8` и сбрасывать `$LASTEXITCODE = 0` |
| **Релиз собирался с версией из csproj, а не из тега** | Тег `v0.3.0` + `<Version>0.2.0</Version>` → exe рапортует 0.2.0 → самообновление предлагает 0.3.0, ставит и снова видит 0.2.0. Вечный цикл. Версия обязана приходить из тега (`-p:Version=`), и её надо проверять через `--version` |
| **Артефакт публиковался без `engine\`** | Приложение запускается и пишет «Движок не установлен» — выглядит как поломка сборки. `publish` и `release` обязаны класть движок внутрь, а сборка — падать, если его нет |
| **Литерал `<script>` внутри `app.js`** | HTML-парсер ищет закрывающий `</script>`, но любой инструмент, который вставляет разметку в страницу, спотыкается о `<script>` в комментарии и рвёт скрипт. Писать «тег script» словами |
| **`ConvertFrom-Json` в PowerShell регистронезависим** | JSON допускает ключи `выключен` и `Выключен` одновременно, а PowerShell считает это дубликатом и падает. Проверять словари через `node`, а не через `ConvertFrom-Json` |
| **Скобка `)` в `echo` внутри блока `if (...)`** | cmd парсит блок целиком, даже если ветка не выполняется, и `)` в тексте закрывает блок досрочно. Скрипт умирает на разборе с невнятным сообщением и кодом 255, успев напечатать половину. Экранировать `^)` или переписать текст без скобок. Ловится `tools\check-encoding.ps1` |
| **`.cmd` с LF вместо CRLF** | cmd требует CRLF, иначе блоки `if/else` разбираются неправильно. Файлы, записанные редактором с настройкой LF, ломаются молча. Ловится `tools\check-encoding.ps1` |
| **Кириллица в `.cmd`** | cmd печатает байты как OEM, в консоли получается «ਥ : ..». Все скрипты сборки — только латиница; русский текст живёт в UI |
| **«Наполовину так, наполовину так»** | Файл, где часть строк CRLF, а часть LF, или часть байтов UTF-8, а часть cp1251, выглядит нормально в одном редакторе и мусором в другом. `tools\check-encoding.ps1` проверяет BOM, валидность UTF-8 и переводы строк по всему репозиторию |
| **Свой `winws` в списке «чужих»** | `DetectForeignWinws()` ищет по имени процесса, поэтому находил и наш собственный. Любая проверка при включённом обходе решала, что мешает чужой winws, и отменяла запуск. Запоминать свои PID-ы и исключать их |
| **Ранний `return` в фоновой операции** | Если обработчик выходит до финального сообщения, кнопка в UI остаётся в состоянии «…» навсегда — выглядит как «не стартует». Каждый выход обязан отправлять терминальное сообщение с причиной |
| **hosts перенаправляет youtube/discord** | Браузер идёт на захардкоженный IP мимо обхода: чужой сертификат или таймаут. При записи hosts предупреждать, если в блок попали сайты, которые и так обходит движок |
| **Файл сообщения коммита внутри репозитория** | `git add -A` после записи `msg.txt` затягивает сам файл в коммит, и появляется мусорный «chore: tidy». Писать сообщение в `%TEMP%` и коммитить `git commit -F <вне репозитория>` — тогда tidy-коммиты не нужны вовсе |
| **`<ApplicationHighDpiMode>` в csproj без вызова** | Свойство только генерирует `ApplicationConfiguration.Initialize()`. Мы настраиваем WinForms руками, поэтому режим оставался SystemAware: при 125 % окно рисуется в 100 % и растягивается — всё мыло. Вызывать `DpiSetup.Apply()` **до** `EnableVisualStyles` |
| **Светлая тема = «белое окно с чёрным терминалом»** | Пока фон логов и цвета строк заданы литералами, смена темы их не трогает. Любой цвет — только переменная в `:root`, тема переопределяет переменные. Ловится `html[data-theme=...]` в selftest |
| **«Отменить» срабатывает через полминуты** | Токен проверялся только между стратегиями, а внутри `Thread.Sleep(5 с)` и пробы с таймаутами. Ждать через `WaitHandle.WaitOne`, токен передавать в пробы — иначе кнопка выглядит мёртвой |
| **`tcp.PayloadLength > 40` в фильтре своего движка** | В user mode уходит **каждый** исходящий пакет с данными: копирование, разбор, отправка обратно. Просадка именно исходящей скорости (входящие ACK мелкие). Ловить ClientHello: `Payload[0] == 0x16 and Payload[1] == 0x03 and Payload[5] == 0x01`, кроме `any-protocol` |
| **Первый UDP-пакет узнаётся только как QUIC/STUN** | Показ экрана Discord начинается с DTLS (`0x16 0xFE`) — не узнан, фейк не отправлен, экран не поднимается при работающем голосе. DTLS распознавать, а тип пакета включать в ключ «первого пакета потока» |
| **`event.data instanceof ArrayBuffer` в воркере** | В рантайме Workers проверка может дать `false` (чужой realm, Uint8Array, Blob). Тогда `TextEncoder` превращает бинарный кадр в строку `[object ArrayBuffer]`, в Telegram уходит текст вместо TLS, и его nginx отвечает `400 Bad Request`. Со стороны — «воркер не работает». Проверять `typeof === "string"`, затем `ArrayBuffer.isView`, затем `arrayBuffer()` |
| **Ошибка воркера отправлена текстом в бинарный поток** | В Cloudflare Worker диагностика уходила `server.send("...")` в тот же WebSocket, где уже идёт TLS: клиент видел «HTTP/1.1 400 Bad Request» посреди рукопожатия и падал с «wrong version number». До старта данных — только close-кадр с причиной |
| **`connect()` без `await socket.opened`** | Ошибка соединения приходит как «Stream was cancelled», и починить нечего: непонятно, что запретил Cloudflare. Ждать `opened`, причину класть в close-кадр (программа её покажет) |
| **Параллельные `writer.write` в воркере** | Две записи в один WritableStream переставляют куски, и TLS-поток на той стороне разваливается. Сериализовать через цепочку промисов |
| **Проверка «релей работает» повтором того же запроса** | `?probe=` в воркере отвечает текстом только в новой версии; старая отвечает 426. Если написано «Expected Upgrade», значит задеплоен старый код, а не «Cloudflare не пускает» |
| **`UpstreamRoutes.Order` вернул пустой список — и навсегда** | Два отказа TCP дают домену два «удара», а `Strikes >= 2` выбрасывал его из перебора. Когда так выбыли все домены, `Order` отдавал пусто, прокси отвечал «нет доступных маршрутов» и не восстанавливался до перезапуска. Удары должны жить столько же, сколько карантин, а `Order` не имеет права возвращать пусто при непустом входе |
| **Фейк только первому UDP-пакету потока** | Discord пересогласовывает DTLS прямо во время звонка. С правилом «один фейк на пятикортеж» каждое следующее рукопожатие шло без обхода: звук рвался, показ экрана пропадал через несколько минут. Фейк нужен на КАЖДЫЙ DTLS ClientHello и STUN Binding Request (с бюджетом), а не на первый пакет типа |
| **UDP-фейк возвращал «обработано»** | `HandleUdp` возвращал `true` после отправки фейка, а `true` в цикле означает «оригинал не отправлять». Настоящий DTLS ClientHello/STUN выбрасывался, рукопожатие не начиналось, клиент повторял — и каждая копия тоже выбрасывалась, пока не кончался бюджет. Симптом: «показ экрана не подключается», «голос хандрит», в логе тишина. Для UDP fake возвращать `false` (фейк — дополнительный пакет); `true` — только для TCP, где куски содержат оригинал |
| **Первый пакет Discord — не STUN и не DTLS** | Это bencode `d1:ad2:i…` (`64 31 3a 61 64 32 3a 69`). Пока его не узнаём, профиль «L7 discord,stun» не применяется к голосу: в zapret2 классификатор называется `--payload=discord_ip_discovery`. Распознавать префикс `d<цифра>:` и фейковать один раз на поток |
| **Проверка аргументов «по списку флагов»** | Наличие `--filter-l7` в бинарнике не значит, что комбинация запустится. Единственная честная проверка — прогнать стратегию через `--dry-run` настоящего движка (`tools/audit-strategies.js`, 16-я проверка CI) |
| **44 запуска `winws` = 44 окна UAC** | У `winws.exe`/`winws2.exe` манифест `requireAdministrator`: каждый старт без прав спрашивает подтверждение. Аудит стратегий должен один раз перезапустить себя через `Start-Process -Verb RunAs` и запускать всех детей уже из повышенного процесса (`tools\audit.cmd`) |
